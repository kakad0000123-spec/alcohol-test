# 2026-08-03 無開孔（僅補扁鐵）選項 + 廠商自刪權限

## 做了什麼
- 形狀加第三選項 `無開孔`：尺寸區隱藏、扁鐵改必填、`perimeter_mm` 存 null、`size_label` 存「無開孔」。
- 尺寸填 0 即時提示改選該選項（廠商原本的行為就是填 0，接住意圖而非丟錯誤）。
- 統計：孔數排除無開孔（判準用 `shape`），扁鐵照計；儀表板與總覽同步改、註腳重寫。
- 廠商可刪自己的紀錄：限自己 contractor 且未寄出；改狀態仍 admin only。

## 為什麼
- 廠商反應「開口太小不修補、大小是 0 但有補扁鐵」送不出去 —— 卡在 `upload.html` 開孔尺寸無條件必填。
- 根因不是驗證太嚴，是資料模型少一個狀態：表單假設「每筆＝一個開孔」，但表單的真正用途是**請款憑證**（一筆＝一件做過的工作）。
- 刪除原本全要 Po 代勞，而這是廠商自己的請款資料，影響他後續提送。

## 踩了坑
- **`middleware.ts` 把 `/api/records/batch` 整條列為 superadmin-only**，vendor 在進到 handler 前就被擋；不測就上線＝功能看起來有做、實際全被擋。已移出清單，改由 handler 分流。
- **`records/[id]/route.ts:62` 的 shape 白名單只認圓/矩**，不改的話這種紀錄被編輯一次（哪怕沒動形狀）shape 就靜默清成 null，「刻意標記 vs 漏填」的區分蒸發。
- 測試腳本自己出兩次包：zsh 陣列是 **1-based**（誤判成權限漏洞）、`${3:+-H "..."}` 在 zsh 不分詞導致整批 400。最後改用 Python 寫測試才穩。

## 否決了什麼/為什麼
- 否決 `NA` / `N/A` 當存值：pandas 等工具預設把 `NA`/`N/A` 讀成空值，匯出的 Excel 一經處理就把「刻意 vs 漏填」的區分洗掉——正好摧毀選它的理由。改用中文 `無開孔`。
- 否決單一個 `無`：樞紐表裡語意太薄（無什麼？）。
- 否決 `perimeter_mm` 存 0：無開孔是「沒有周長這個概念」，不是周長為零；存 0 會汙染日後的平均值。
- 否決用 `perimeter_mm == null` 當統計排除判準：會把真正漏填的紀錄一起藏起來，那些該被看見、該去問廠商。
- 否決為「開孔但不修補也沒扁鐵」設計欄位：Po 指出這種情況廠商根本不會填（沒工作就不請款），不該進系統。
- 廠商刪除**未**全開：已寄出的擋掉（公司端已收到的請款憑證，不該單方面消失、照片一併不可復原）。Po 描述的「填錯要重填」都發生在待寄階段，所以不影響實際需求。要全開只需拿掉 handler 那一個 status 判斷。

## 為什麼這個系統做不出「完成率」（Po 2026-08-03 原話）
> 「我現在沒有寫總量的原因也是因為可能開孔不需要做補強」

完成率在此案**結構上不成立**：分母（總開孔數）本來就不等於工作量，因為有些開孔不需補強、有些沒開孔卻要補扁鐵。
這比 2026-07-10 記的「Po 還沒確認目標數」更根本——那句聽起來像等個數字就能做，其實不是。
→ 未來不要再提議做整體進度條／完成率，除非 Po 另外給各區的「應補強數」當分母。
